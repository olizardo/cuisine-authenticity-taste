# Optimization Plan for Hierarchy Queue

## Diagnosis: Why are the hierarchy models so slow?

After comparing the `hier_*.R` scripts with the previously cached `run_models_*.R` scripts, I have identified three primary reasons why the current models are taking 6+ hours to fit:

1. **Unstandardized Continuous Predictors (The main bottleneck):** 
   The cached models used *categorical/factor* variables (`age.f`, `inc.f`, `educ.f`), which are all dummy-coded to 0/1, meaning they inherently share the exact same scale. 
   The hierarchy models, however, use *continuous* predictors that are mean-centered but **not scaled** (`scale(x, center = TRUE, scale = FALSE)`). This means variables like `age_c` (ranging from roughly -30 to +40) are being evaluated in the same space as `social_c` (ranging from -2 to +2). HMC/NUTS samplers struggle massively with variables on wildly different scales. It forces the sampler to take incredibly tiny steps to navigate the posterior, ballooning your sampling time.
2. **Matrix Overhead:** 
   The base `scale()` function in R returns a *matrix*, not a vector. Passing a matrix column into a `brms` formula introduces unnecessary internal formatting overhead during data compilation.
3. **Underutilized CPU Cores:** 
   The scripts are currently set to `cores = 2` (meaning 4 chains run 2 at a time, doubling the time). This was a necessary safeguard when you were using `rstan` (which crashed the server's RAM). However, since I migrated your environment to `cmdstanr`, the memory footprint of sampling is practically negligible (< 50MB per chain). We can safely use all 4 cores without risking an Out-Of-Memory crash.

## The Optimization Plan

To guarantee the fastest convergence time possible while maintaining mathematical rigor, I propose the following adjustments to all `hier_*.R` scripts:

1. **Fully Standardize Predictors:**
   Change the `mutate()` pipeline to use `as.numeric(scale(x, center = TRUE, scale = TRUE))`.
   *Note: Standardizing (Mean = 0, SD = 1) makes the posterior geometry "spherical", which the NUTS sampler traverses effortlessly. If you need to report unstandardized coefficients later, you can simply multiply the posterior estimates by the original standard deviations.*
2. **Maximize Core Usage:**
   Change `cores = 2` to `cores = 4`. This alone will instantly cut the sampling time in half.
3. **(Optional) Relax `adapt_delta`:**
   Currently, `adapt_delta = 0.95`. This is a very strict setting that forces small step sizes. With standardized predictors, the sampler will be much healthier, and we can safely drop this to `0.90` (or leave it at 0.95 if you want to be overly cautious—standardizing will still make it lightning fast).
