# Plan: Fix Environment and Run Models in Background

## 1. Diagnosis
The previous attempts to run the background script hung because:
1. **Network Sandbox & Prompts:** The background terminal (`bash`) lacks network access and is non-interactive. When `Rscript` launches, the `renv` environment detects broken package cache links and missing packages (like `brms`). It either attempts to fetch them (which fails silently/hangs due to no network) or prompts for user confirmation (which hangs indefinitely in a background job).
2. **Missing Dependencies:** The `brms` package (and potentially `cmdstanr` / `rstan`) is not fully installed or synced in the project's library. 

## 2. Step-by-step Implementation Plan

### Step 1: Repair the R Environment in the Active Session
Unlike the bash terminal, the active Positron R console *has* network access. We will use it to:
- Run `renv::restore()` or manually install `brms`, `tidybayes`, and `modelsummary`.
- Ensure all packages are fully compiled and cached locally so that background bash scripts don't need network access to load them.

### Step 2: Set Up the Stan Backend
Bayesian models require a compiler. We will install the CmdStan backend (if needed) using `cmdstanr::install_cmdstan()` directly in the active R session, ensuring it completes successfully and the toolchain works.

### Step 3: Harden the Background Script
We will edit `run_models.R` to:
- Disable any interactive `renv` prompts (e.g., `Sys.setenv(RENV_CONFIG_PPM_ENABLED=FALSE)` or `options(rlang_interactive = FALSE)`).
- Add informative print statements at every step.
- Reduce the model iterations temporarily (e.g., `iter = 10`) for a rapid test run.

### Step 4: Verify with a Dry Run, Then Launch
- We'll launch the modified script via `bash` and verify the `model_run.log` shows actual Stan sampling progress.
- Once the dry run completes successfully, we will restore the `iter = 2000` count and launch the final, long-running job.
